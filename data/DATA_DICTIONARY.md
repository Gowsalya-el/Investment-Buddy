# Investment Buddy — Data Dictionary

All portfolio and growth calculations in this application are derived **only** from
the two datasets described below. No external market data is used.

---

## 1. `products.csv` — Available Investment Products

Source: *investment-products-dummy-dataset-Final* (provided).

| Column | Description |
|---|---|
| `productID` | Unique product identifier |
| `productName` | Display name of the product |
| `productType` | Instrument type (e.g. State Savings, Fixed Deposit, Bond Fund, ETF, Pension Fund…) |
| `productTerm` | Fixed term if applicable (e.g. `2 Years`), blank if open-ended |
| `productRisk` | Risk band label: `Low`, `Low-Medium`, `Medium`, `Medium-High`, `High` |
| `riskScore` | Numeric risk 1 (safest) → 10 (riskiest) |
| `expectedReturnPercentage` | Expected annual return %, **used directly** for growth predictions |

### Portfolio buckets (derived from `productType`)
Products are grouped into the four portfolio categories requested:

| Bucket | productType values |
|---|---|
| **Savings Account** | State Savings, Savings Account, Money Market Fund |
| **Fixed Deposits** | Fixed Deposit |
| **Policies** | Insurance Investment |
| **Funds (stocks / bonds / pension)** | Bond Fund, Balanced Fund, Managed Investment Fund, Equity Fund, Stocks & Shares, Retirement Account, Pension Fund, ETF, Index Fund, Real Estate Investment Trust, Property Fund, Sector Fund, Cryptocurrency, Thematic ETF, Emerging Markets ETF, Individual Stock, Crowdfunding, P2P Lending |

---

## 2. `customers.csv` — Customer Records

Source: *HackathonCustomerAndReferenceDummyTables-Final* (schema provided via header row).
The original file arrived as a binary Excel export that could not be read, so a
**sample dataset matching the exact given schema** was created for the app to run on.
Replace this file with the real export (same columns) at any time.

| Column | Description |
|---|---|
| `customerID` | Unique customer identifier (drives the per-customer interface) |
| `firstName` | Customer first name |
| `lastName` | Customer last name |
| `dateOfBirth` | ISO date `YYYY-MM-DD` — age is derived from this (demographic input) |
| `addressLine1` | Address line 1 |
| `addressLine2` | Address line 2 (optional) |
| `city` | City (demographic) |
| `country` | Country (demographic) |
| `riskAppetite` | Stated risk tolerance — one of the five bands used by products (see below) |
| `accountBehaviour` | Behavioural profile (see below) |
| `investableAmount` | **Added field** — amount (EUR) the customer wishes to invest. If your real export lacks this, the interface lets you type it in per customer. |

### `riskAppetite` values (aligned to product risk bands)
`Low`, `Low-Medium`, `Medium`, `Medium-High`, `High`

### `accountBehaviour` values (added, documented)
The header row indicated an `accountBehaviour` column but no value list was supplied,
so the following behavioural categories are defined and used:

| Value | Meaning | Effect on portfolio |
|---|---|---|
| `Cautious Saver` | Prioritises safety, rarely moves money | Nudges allocation one notch **safer** |
| `Regular Saver` | Saves steadily, low activity | Slight safe nudge |
| `Balanced` | Neutral saver/investor | No behavioural adjustment |
| `Frequent Trader` | Actively trades, comfortable with movement | Nudges allocation one notch **riskier** |

---

## 3. `customer_portfolios.json` — Saved Recommendations (output)

Generated by the app when a recommendation is saved. Each entry stores the customer,
the chosen risk level, the allocation, currency amounts, and the yearly + 5-year
growth projection so it can be referenced in future.

---

## Calculation summary

1. **Risk level** for a customer starts from `riskAppetite`, is adjusted by
   `accountBehaviour`, and can be overridden by the on-screen risk dropdown.
2. **Allocation weights** across the four buckets are defined per risk level
   (safer levels weight Savings / Fixed Deposits / Policies more heavily; riskier
   levels weight Funds more heavily).
3. Within each bucket, the customer's money is spread across that bucket's products,
   and each product's `expectedReturnPercentage` is applied.
4. **Blended annual return** = sum of (allocation % × product return %), computed only
   from dataset values.
5. **Growth** is compounded annually and projected yearly across a 5-year horizon.
